# Tareas — Spec 001

- [x] **T1** Usuarios, roles y permisos con roles por defecto y permiso DRF `require()`. (Historia 1)
- [x] **T2** Catálogo: categorías, unidades, productos, presentaciones con factor, IVA. (Historia 2)
- [x] **T3** Inventario: bodegas, kardex, existencias, `record_movement` idempotente; API de entradas, existencias y kardex. (Historias 3 y 8)
- [x] **T4** Ventas: venta + líneas (precio, IVA por línea) + descuento de stock en una transacción; API idempotente con `client_uuid`. (Historia 4)
  - Descuentos por línea quedan para la T5 o una tarea propia (requieren permiso y tope por rol).
- [x] **T5** Caja: turnos, base, pagos por medio, arqueo y cierre. (Historia 6)
  - Un turno abierto por caja física; pago mixto con vueltas solo en efectivo; toda venta pertenece a un turno.
  - Vender exige `cash.operate` (vender y cobrar es un solo paso). El rol Ventas necesitará un flujo de pedidos que caja cobre: tarea pendiente.
- [x] **T6** Anulación y devolución con permiso `sales.void`. (Historia 7)
  - Anular = venta completa y solo con su turno abierto. Después del cierre se usa una devolución, que reembolsa desde el turno abierto actual.
- [x] **T7** Autenticación para la PWA y API de usuarios y roles para el administrador. (Historia 1)
  - Sesión de Django en cookie HttpOnly + CSRF (sin dependencias nuevas). La PWA y la API deben servirse desde el mismo dominio.
- [x] **T8** Frontend PWA: inicio de sesión, POS, entradas a bodega, existencias. (Historias 3, 4 y 8)
  - React + Vite + TypeScript, sin librerías de UI ni router. Caja: elegir caja, abrir turno, vender (lector o búsqueda), pago mixto y cierre con arqueo a ciegas.
  - Lo "PWA" (instalable, service worker, sin conexión) queda para la T9.
- [x] **T9** Modo sin conexión: catálogo en IndexedDB, cola de ventas, sincronización y bandeja `needs_review`. (Historia 5)
  - Service worker y manifest escritos a mano (sin dependencias). Ver "Modo sin conexión" en docs/arquitectura.md.
  - No verificado en el panel del navegador de Claude (Electron no registra service workers): hay que probar la instalación en Chrome o Edge.
- [x] **T10** CI con GitHub Actions (pytest) y despliegue con Docker + PostgreSQL.
  - Un contenedor (gunicorn + WhiteNoise sirviendo el frontend) + PostgreSQL. El CI construye la imagen y ejecuta `scripts/smoke-test.sh`. Guía en docs/despliegue.md.
  - [x] CI: `.github/workflows/tests.yml` corre migraciones y pytest en Python 3.12 y 3.14 en cada PR.
